# Smartphone Addiction Prediction -- Kaggle Playground Series S6E8

Binary classification: predict whether a user is smartphone-addicted (`addicted_label`), evaluated on ROC-AUC.

**Result:** 0.96602 AUC · Playground Series S6E8

---

## Problem

Given per-user behavioral data (screen time, app usage, sleep, stress level, demographics), predict smartphone addiction. The dataset is synthetically generated by Kaggle from real survey data.

Target is imbalanced: ~70% Addicted vs ~30% Not Addicted. Since the metric is ROC-AUC, this is manageable, but `scale_pos_weight` was applied to give the minority class more weight.

---

## Key EDA Findings

Screen-time features dominate everything else by a wide margin:

| Feature | Correlation with Target |
|---|---|
| `daily_screen_time_hours` | 0.61 |
| `weekend_screen_time` | 0.59 |
| `social_media_hours` | 0.53 |

`sleep_hours`, `age`, and `notifications_per_day` carry virtually no linear signal. `gender` and `stress_level` showed less than 2% variation in addiction rates across categories. However, dropping any of these low-signal features hurt the score (0.965 dropped to 0.894). Even weak features contribute small signals that add up -- do not drop based on low correlation alone.

The crossover at **7 hours daily screen time** (where addicted users dominate) directly inspired the threshold-based feature `high_screen_time`.

---

## Feature Engineering

13 features engineered across 4 types, applied identically to train and test before any split:

### Threshold Flags -- binary signals at EDA crossover points
| Feature | Logic |
|---|---|
| `high_screen_time` | daily screen time > 7 hrs |
| `high_weekend_screen` | weekend screen time > 10 hrs |
| `high_social_media` | social media hours > 2 hrs |

### Gap Features -- weekend vs weekday behavioral shift
| Feature | Logic |
|---|---|
| `weekend_gap` | weekend screen time minus daily screen time |
| `leftover_screen` | daily screen time minus social media, gaming, and work hours (unattributed usage) |

### Ratio Features -- proportional behavior relative to total screen time
| Feature | Notes |
|---|---|
| `work_ratio` | strongest ratio feature |
| `social_ratio` | social media hours as proportion of total screen time |
| `weekend_weekday_ratio` | weekend vs weekday usage ratio |
| `gaming_ratio` | gaming hours as proportion of total screen time |
| `apps_open_per_hour` | app open frequency normalized by screen time |

### Ordinal Bins -- gradient signal stronger than a single threshold
`screen_time_bin`, `weekend_screen_bin`, `high_social_bin` -- each split into 4 ordered buckets based on EDA distributions. `screen_time_bin` was a top feature in the final model.

Two features (`notif_per_open`, `entertainment_ratio`) were tested and removed as they hurt the score.

---

## Preprocessing

Three-group `ColumnTransformer` inside a sklearn `Pipeline` so imputers fit only on training data:

- **Numerical** -- median imputation (robust to skewed distributions)
- **Ordinal** (`stress_level`) -- mode imputation + ordered encoding (Low < Medium < High)
- **Nominal** (`gender`) -- mode imputation + one-hot encoding

Stratified 80/20 split to preserve the 70/30 class balance.

---

## Hyperparameter Tuning

3-fold Stratified CV inside Optuna objective. XGBoost trained on GPU (`device=cuda`, `tree_method=hist`) which made running 200 trials feasible.

Key finding: 200 trials only improved over 100 by +0.00003 AUC (best params found at trial 178). 25-30 trials is enough for most cases.

Best params after 200 trials: `n_estimators=1653`, `max_depth=5`, `learning_rate=0.113`, `subsample=0.973`, `colsample_bytree=0.695`, `min_child_weight=30`

---

## Score Progression

| Step | Public AUC |
|---|---|
| Baseline LightGBM | 0.96138 |
| LightGBM + Optuna | 0.96488 |
| XGBoost + Optuna (100 trials) | 0.96511 |
| XGBoost + Optuna (200 trials) | 0.96514 |
| + `weekend_gap` and `leftover_screen` | 0.96578 |
| + ratio features | **0.96602** |

Feature engineering moved the score more than hyperparameter tuning did.
