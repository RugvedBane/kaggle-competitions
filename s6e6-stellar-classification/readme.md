# Stellar Classification -- Kaggle Playground Series S6E6

Multiclass classification: predict whether an astronomical object is a **Galaxy**, **Star**, or **Quasar (QSO)**, evaluated on balanced accuracy.

**Result:** 0.9554 CV balanced accuracy · Public score 0.95548 · Rank 1988 / 2817 · Playground Series S6E6

---

## Problem

Given photometric and spectroscopic measurements from the Sloan Digital Sky Survey (SDSS), classify each object into one of three classes: Galaxy, Star, or QSO. The dataset is synthetically generated by Kaggle from real SDSS data.

Key columns: photometric bands (u, g, r, i, z), sky coordinates (alpha, delta), redshift, spectral type, and galaxy population.

---

## Feature Engineering

4 color index features built from adjacent photometric bands -- standard practice in astronomy since color indices capture spectral shape better than raw magnitudes:

| Feature | Formula | Reasoning |
|---|---|---|
| `u_g` | u - g | UV to green color index |
| `g_r` | g - r | Green to red color index |
| `r_i` | r - i | Red to near-infrared index |
| `i_z` | i - z | Near-infrared color index |

Categorical features (`spectral_type`, `galaxy_population`) encoded with one-hot encoding.

---

## Modeling

Two models compared:

**CatBoost** -- 1000 iterations, depth=8, lr=0.05, MultiClass loss. Tested first but XGBoost outperformed it.

**XGBoost with early stopping (final)** -- up to 5000 trees with `early_stopping_rounds=100`, stopping training automatically when validation balanced accuracy plateaus. Best iteration landed around 1400 trees, which was used for the final submission trained on the full dataset.

5-fold Stratified CV to preserve class balance across folds.

---

## What Worked
- Color index features added meaningful signal on top of raw photometric bands
- Early stopping removed the need to guess `n_estimators` -- let the validation performance decide
- `redshift` was the dominant feature by a large margin, which aligns with how astronomers distinguish quasars (high redshift) from stars and galaxies

## What I'd Do Differently
- Run Optuna for hyperparameter tuning instead of using default params
- Try stacking CatBoost and XGBoost predictions instead of picking one
- Add more EDA -- understanding the redshift distribution by class earlier would have shaped FE better
