# F1 Pit Stop Prediction — Kaggle Playground Series S6E5

Binary classification task: predict whether an F1 car will pit on the **next lap** (`PitNextLap`), evaluated on ROC-AUC.

**Result:** 0.94793 AUC · Rank 1646 / 3022 · First Kaggle competition

---

## Problem

Given per-lap telemetry for each car in a race — tyre age, lap time, compound, stint number, position — predict the probability of a pit stop on the next lap. The dataset is synthetically generated by Kaggle from real F1 data.

---

## Approach

### Preprocessing
- Dropped `id`, `Driver`, `Race`, `RaceProgress`
- One-hot encoded `Compound` (tyre type: Soft / Medium / Hard / Intermediate / Wet)

### Feature Engineering
| Feature | Reasoning |
|---|---|
| `TyreLife_squared` | Tyre degradation is non-linear — older tyres degrade faster |
| `OldTyre` | Binary flag for tyres > 40 laps — empirically high pit-risk zone |
| `LapTime_rolling` | 3-lap rolling mean within each stint — smooths noise |
| `LapTime_vs_avg` | Deviation from rolling mean — captures sudden pace drops |

### Models Trained

Compared XGBoost, LightGBM, CatBoost, and a simple average blend of XGB + LGBM. All models used the same base config (500 estimators, lr=0.05, max\_depth=6, subsample=0.8) for a fair comparison.

Final submission used **XGBoost with early stopping** (up to 5000 trees, lr=0.02, `early_stopping_rounds=50`) — training stops automatically when validation AUC plateaus, which avoids having to guess the right `n_estimators`.

---

## What Worked
- Early stopping on XGBoost outperformed the fixed 500-tree configs
- `TyreLife` and its squared form were the strongest features — tyre age is the main driver of pit strategy
- Rolling lap time deviation helped capture degradation signal beyond raw lap time

## What I'd Do Differently
- Use cross-validation instead of a single 80/20 split — one split isn't enough to trust the validation AUC
- Extract features from `Driver` and `Race` before dropping them (e.g., team-based pit strategies, circuit-specific patterns)
- Try Optuna or a proper hyperparameter search instead of manual tuning
- Explore target encoding for categorical features
